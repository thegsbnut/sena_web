# Job badge หน้าชื่อผู้เล่น — design

สถานะ: อนุมัติแล้ว · ทำเสร็จบน branch `claude/bold-dijkstra-s6qjbu` (ยังไม่ merge main) · mockup: `docs/superpowers/mockups/2026-11-13-badge-mockup.html` (เปิดในเบราว์เซอร์ ปุ่ม "Job ✦") · ฉบับออนไลน์ https://claude.ai/artifact/Xx5sXoQEGX13JgGAvqe9FP

## ทำไม
ให้ผู้เล่นอยากมาตีบ่อยขึ้นและสนุกกับการไต่ระดับ: วงกลมหน้าชื่อในการ์ดจองเปลี่ยนเป็น badge แบบ RPG "เปลี่ยน job" ตามจำนวนครั้งที่มาตี บวกมงกุฎสำหรับแชมป์ Cup โทนเบียวขั้นสุด

## เป้าหมาย
- badge หน้าชื่อในการ์ดจอง (ตัวจริง + สำรอง) แทนตัวย่อชื่อเดิม ขนาด 35px เท่าเดิม
- ระดับมาจากจำนวนครั้งที่มาตีจริง นับอัตโนมัติ **ได้แล้วอยู่ตลอด ไม่ลดขั้น**
- ผู้เล่นเลือกสาย (job line) เองได้ ไม่เลือก = ระบบสุ่มให้
- แชมป์ Cup โชว์มงกุฎพร้อมจำนวนครั้ง

## ไม่ทำ (รอบนี้)
- ไม่ใส่ยอดตั้งต้นย้อนหลัง: ระบบยังไม่ได้ใช้จริง ทุกคนเริ่ม Novice พร้อมกันวันเปิดใช้ (เพิ่มทีหลังได้ถ้าต้องการ)
- ไม่โชว์ badge ในข้อความ LINE, หน้าบิล, หน้าจัดก๊วน (แท็บจัดก๊วนซ่อนอยู่)
- ไม่นับข้ามก๊วน: Sena กับ 88 นับแยก (ข้อมูลแยกกันอยู่แล้ว)
- ไม่เดาสายจากสไตล์การตี (ระบบไม่มีข้อมูล)

## Anti-goals
- ห้ามทำให้หน้าจองโหลดช้าลงจนรู้สึกได้ (เจ้าของไม่ยอมให้ LIFF ช้า — ดู HANDOFF เรื่องรูปโปรไฟล์ LINE): ไม่โหลดรูปภายนอก ไม่โหลดไลบรารี รูปเป็น SVG ที่สร้างในโค้ด
- ห้ามให้การเลือกสายของคนหนึ่งไปชน revision ของเอกสารจอง (ต้องไม่ทำให้คนอื่นจองแล้วเจอ 409 บ่อยขึ้น)

### การเลือกสาย
- ยังไม่เลือก → สุ่มแบบคงที่จาก `player_id` (hash แล้ว mod 5) เปิดกี่ครั้งก็ได้สายเดิม
- ผู้เล่นที่ล็อกอิน LINE และผูกชื่อแล้ว (approved) เปลี่ยนสายของตัวเองได้ตลอด ไม่มีคูลดาวน์ ขั้นไม่รีเซ็ต (ขั้นมาจากจำนวนครั้ง)
- เครื่องหมาย **!** สีเหลืองเด้งบน badge **ของตัวเองเท่านั้น** เมื่อยังไม่เคยเลือกสายและถึง Job 1 แล้ว (คนอื่นไม่เห็น เพื่อไม่ให้การ์ดรก)
- ผู้จัดเปลี่ยนสายให้ผู้เล่นไม่ได้ในรอบนี้

### แชมป์
- นับจำนวน Cup ที่ได้ 🥇 จาก Cup history ทั้งหมดของก๊วน (ใช้ `Sena.cupAwards` ต่อรายการ, จับคู่ชื่อแบบ `cupPlayerKey` เหมือน award เดิม ทั้ง `name` และ `thai`)
- มงกุฎทองมุมขวาบน ≥2 ครั้งมีตัวเลข; แชมป์ Cup ล่าสุดมงกุฎเรืองแสงกะพริบ
- ในการ์ดจอง เอา 🥇 หน้าชื่อออก (มงกุฎแทน) แต่ 💩 ของ Cup ล่าสุดยังอยู่หน้าชื่อเหมือนเดิม; ข้อความ LINE ไม่เปลี่ยน

## การนับครั้งที่มาตี (approach B — เจ้าของเลือก)
- ตารางใหม่ใน `DB` (สร้าง lazy): `attendance (club TEXT, session_date TEXT, player_id TEXT, PRIMARY KEY (club, session_date, player_id))`
- ใน cron ประจำวัน (`scheduledBookings`, 01:00 ไทย) หลัง `mutateBooking` ของแต่ละก๊วน: ทุก session ที่ `date < วันนี้ (เวลาไทย)` และไม่ `skipped` → เอา `registrations.slice(0, capacity)` ที่ไม่ใช่ `guest` และ `playerId` อยู่ใน roster → `INSERT OR IGNORE`
  - idempotent: รันซ้ำไม่นับซ้ำ; cron พลาดไปหลายวันก็ยังเก็บได้ เพราะ session อยู่ในเอกสาร 30 วัน
  - คนที่ผู้จัดถอนชื่อออกก่อนตี 1 จะไม่ถูกนับ (ผู้จัดใช้แก้กรณีไม่มา)
  - เพื่อนที่ถูกชวน (`invitedBy`) เป็นผู้เล่นใน roster → นับ; แขก (`guest`) ไม่นับ
- ตาราง `player_jobs (club TEXT, player_id TEXT, line TEXT, updated_at TEXT, PRIMARY KEY (club, player_id))` — แยกจากเอกสารจอง จึงไม่ชน revision ของการจอง (anti-goal); เขียนแบบ upsert แถวเดียวของตัวเอง ไม่ต้องมี revision

## ข้อมูลที่ส่งไปหน้าเว็บ
`/api/booking` GET: แต่ละคนใน `roster` เพิ่ม `badge: { plays, line, chosen, titles, latestChamp }` (อ่าน `attendance` แบบ `GROUP BY player_id` + `player_jobs` + cup history ในครั้งเดียวคู่กับข้อมูลที่อ่านอยู่แล้ว ด้วย `Promise.all`)
- frontend คำนวณขั้น/ดาวเองจาก `plays` (กติกาอยู่ในไฟล์เดียวที่ทั้ง Worker และเบราว์เซอร์ใช้ได้ถ้าจำเป็น)
- การเปลี่ยนสาย: POST `/api/booking` `{ action: 'job', line }` ผ่าน Origin check, ต้อง member approved, `line` ต้องเป็น 1 ใน 5, เขียน `player_jobs` ของ `member.link.player_id` เท่านั้น

## หน้าเว็บ
- ไฟล์ใหม่ `public/job-badges.js` (vanilla, `globalThis.SenaJobs`: กติกา, ชื่อ job, `badgeHtml(badge, size, { mine })`) + `public/job-badges.css` (animation, มงกุฎ, ดาว, !) — ยก SVG จาก mockup ฟังก์ชัน `jobSvg`/`racketV`/`shuttleV`/… และ `<defs>` (gradient/filter/clipPath) ที่ใช้เฉพาะ job style; ใส่ `<defs>` ลงหน้าครั้งเดียว
- `public/booking.js` บรรทัดที่วาด `booking-avatar` (~510) เปลี่ยนเป็น badge; `<small>` ใต้ชื่อเพิ่มชื่อ job เช่น `Floor Annihilator · ↻ ขาประจำ`
- กด badge ของตัวเอง → แผ่นเลือกสาย 5 ปุ่ม (รูป Job 1 ของแต่ละสาย + ชื่อไทย/อังกฤษ) → POST → โหลดข้อมูลใหม่
- ข้อความทั้งหมดผ่าน `html()` ก่อนใส่ `innerHTML`
- `prefers-reduced-motion` → หยุด animation ทั้งหมด
- bump `?v=` ของไฟล์ที่แก้ใน `court.html`/`liff.html`

## Approaches ที่พิจารณา
| | วิธี | ข้อดี | ข้อเสีย |
|---|---|---|---|
| A | นับจากรายชื่อในบิล + ยอดตั้งต้น | ตรงกับคนที่มาจริงที่สุด | ต้องทำบิลทุกครั้ง; 88 ยังไม่ใช้บิล |
| **B (เลือก)** | cron บันทึกตัวจริงจากการจองทุกคืน | ได้ทั้งสองก๊วน ไม่พึ่งบิล ไม่มีงานเพิ่มให้ผู้จัด | นับคนลงชื่อแล้วไม่มา ถ้าผู้จัดไม่ถอนชื่อออก |
| C | ผู้จัดกรอกเอง | ง่ายสุด | ผู้จัดต้องอัปเดตตลอด ไม่ยั่งยืน |

สไตล์ภาพที่ลองก่อนได้ข้อสรุป (อยู่ใน mockup): เหรียญ, 16-bit, 32-bit, เบียว, อนิเมะแบด → เจ้าของเลือก **Job tree**

## เทส (node --test, D1 จำลอง)
- cron: บันทึกเฉพาะ session ที่ผ่านไปแล้ว, ไม่นับแขก, รันซ้ำไม่นับซ้ำ, ไม่นับ waitlist
- `/api/booking` GET มี `badge` ถูกต้อง (plays, สุ่มคงที่เมื่อไม่ได้เลือก, titles จากหลาย Cup)
- POST job: ต้อง approved, line ไม่ถูกต้อง → 400, เขียนได้แค่ของตัวเอง, ไม่แตะ revision ของ booking
- กติกาขั้น/ดาว (pure function) ครบทุกขอบ: 4/5, 14/15, 29/30, 59/60, 180+
- ไฟล์เทสใหม่ต้องเพิ่มชื่อใน script `test` ของ `package.json`

## เรื่องที่ปล่อยให้คนทำตัดสินใจ
- โครงฟังก์ชัน/ชื่อไฟล์ภายใน, วิธีสุ่ม hash (ขอแค่คงที่และกระจายพอ)
- รายละเอียดหน้าตาแผ่นเลือกสาย (ตามสไตล์ปุ่ม/การ์ดที่มีอยู่ใน `booking.css`)
- ปรับรายละเอียดภาพ SVG ได้ถ้าดูไม่ออกที่ 35px แต่คงแนวคิดแต่ละ job ตามตาราง
