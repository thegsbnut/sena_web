# สปอนเซอร์วันแข่ง Cup

ดีไซน์ภาพ (รีวิวแล้ว): https://claude.ai/artifact/FN52z4ubE35s3pBpiFZZof

## เป้าหมาย
- ผู้เล่นเลือกวันแข่ง Cup ของก๊วนตัวเองในหน้าจอง แล้วลงชื่อเป็นสปอนเซอร์ พร้อมระบุของรางวัลที่จะมอบ
- บอทประกาศขอบคุณ (เชิดชู) สปอนเซอร์ในกลุ่ม LINE ของก๊วนนั้นทันที
- ระหว่างช่วงแสดง การ์ด Flex ของ Badbot ทุกใบของก๊วนนั้นมีแถบชื่อสปอนเซอร์ต่อท้าย **ยกเว้นการ์ดน้องขุนเงิน**
- Sena กับ 88 แยกกันทั้งหมด (ข้อมูล, การ์ด, ช่วงแสดง)

## ไม่ใช่เป้าหมาย
- ไม่มีรูปของรางวัล ไม่มีจำนวนเงิน ไม่มีการติดตามว่าแจกของแล้วหรือยัง
- ไม่ใช้ Push API ไม่ใช้ cron
- ไม่มีขั้นตอนอนุมัติจากผู้จัด (ลงแล้วขึ้นเลย ผู้จัดลบทีหลังได้)
- คนนอกก๊วนลงเองไม่ได้ (ผู้จัดลงแทน)

## Approaches
- **A (เลือก): ตารางแยก `cup_sponsors` หนึ่งแถวต่อสปอนเซอร์ + คำนวณช่วงแสดงตอนสร้างการ์ด** — แก้/ลบรายแถวไม่ชนกับเอกสารจองที่ถูกเขียนบ่อย, การ์ด LINE อ่านแค่ query เดียวโดยไม่ต้องโหลดเอกสารจองทั้งก้อน
- B (ไม่เลือก): เก็บใน JSON ของเอกสารจอง (`club_state` booking doc) ต่อ session — ทุกการลงสปอนเซอร์จะไปชน revision กับการจอง/ถอน และการ์ดอันดับ/ผล Cup ต้องโหลดเอกสารจองเพิ่ม; session ถูกลบหลัง 30 วัน ทำให้การ์ดผล Cup หาสปอนเซอร์ไม่เจอ
- C (ไม่เลือก): เก็บช่วงแสดง (start/end) ลงฐานข้อมูลตอนบันทึก — ต้องคำนวณใหม่ทุกครั้งที่มีคนลง/ลบ/ผู้จัดย้ายวัน Cup เสี่ยงค่าค้างผิด

## ใครทำอะไรได้
- **ผู้เล่น:** ต้องผ่านกติกาเดียวกับการจอง (`LINE_MEMBER_AUTH_ENABLED=true` = ล็อกอิน LINE + ผูกชื่อกับก๊วนนั้นแล้ว; ปิดอยู่ = เลือกชื่อเหมือนตอนจอง) ชื่อที่โชว์ = ชื่อผู้เล่นที่ผูก (`player_id`) ไม่พิมพ์เอง
  ลงได้ 1 รายการต่อวันแข่ง แก้/ยกเลิกของตัวเองได้จนถึงเวลาเริ่มรอบของวันนั้น
- **ผู้จัด (admin cookie):** ลงแทนได้โดยพิมพ์ชื่อผู้สนับสนุนเอง (`player_id` = NULL, เช่น ร้านอุปกรณ์) ลงแทนได้หลายรายการ, แก้/ลบได้ทุกแถวทุกเวลา (รวมหลังแข่ง)
- สูงสุด **10 รายการต่อก๊วนต่อวันแข่ง**

## ข้อมูล
ตารางใหม่ใน `schema.js` (เพิ่มที่นี่เท่านั้น — `test-schema.mjs` ตรวจ) ใน `DB`:
```
cup_sponsors (
  id TEXT PRIMARY KEY,           -- crypto.randomUUID()
  club TEXT NOT NULL,            -- 'sena' | '88'
  cup_date TEXT NOT NULL,        -- YYYY-MM-DD วันแข่ง
  player_id TEXT,                -- NULL = ผู้จัดลงแทน
  display_name TEXT,             -- ใช้เมื่อ player_id NULL; ปกติแสดงชื่อปัจจุบันของ player_id
  prize TEXT NOT NULL,
  award TEXT NOT NULL,           -- champ | runnerUp | third | last | all | other
  award_note TEXT,               -- ใช้เมื่อ award = other
  message TEXT,
  hidden INTEGER NOT NULL DEFAULT 0,  -- 1 = วันนั้นไม่ใช่ Cup แล้ว (ซ่อน ไม่ลบ)
  created_at INTEGER NOT NULL,
  updated_at INTEGER NOT NULL,
  revision INTEGER NOT NULL DEFAULT 1
)
index (club, cup_date); unique index (club, cup_date, player_id) WHERE player_id IS NOT NULL
```
- ข้อความ: trim, ยุบช่องว่าง, NFC; `prize` 1–60 ตัวอักษร, `award_note` 1–30 (บังคับเมื่อ other), `message` 0–60, `display_name` 1–30
- แก้/ลบ = optimistic concurrency `WHERE id=? AND revision=?` → ไม่ชนตอบ 409
- เพดาน 10 รายการ: ใช้ `INSERT … SELECT … WHERE (SELECT COUNT(*) …) < 10` คำสั่งเดียว (ไม่ check-then-insert)
- ชื่อแสดงอ่านจาก roster ปัจจุบันด้วย `player_id` (เปลี่ยนชื่อแล้วตามเอง เหมือน Leaderboard); ผู้เล่นถูกลบจาก roster → ใช้ `display_name` ที่ snapshot ไว้ตอนบันทึก (จึงเก็บ `display_name` ทุกแถว)
- เก็บถาวร ไม่ลบอัตโนมัติ (การ์ดผล Cup ใช้)

## วันไหนเป็นวัน Cup
- ลง/แก้ได้เฉพาะ session ในหน้าจองที่ `isCup` เป็นจริง, ไม่ `skipped`, ยังไม่เริ่ม — จึงลงล่วงหน้าได้เท่าที่หน้าจองเปิด (`settings.weeks`)
### ย้ายวัน Cup = สปอนเซอร์ย้ายตาม
สปอนเซอร์ตั้งใจให้ "Cup เดือนนั้น" ไม่ใช่วันที่ ผู้จัดย้าย Cup ในหน้าผู้จัดด้วยการติ๊กออกวันหนึ่ง/ติ๊กอีกวัน แล้วบันทึก (`action=cupCalendar` ใน `booking.js`)
- หน้าผู้จัด: ทุกวันที่จะถูกติ๊กออกและมีสปอนเซอร์ (`hidden=0`) ขึ้นแถวก่อนปุ่มบันทึก
  `ส. 12 ธ.ค. มีสปอนเซอร์ 3 คน → ย้ายไป [ ▾ ]` ตัวเลือก = วัน Cup อื่นที่ยังไม่เริ่ม (ตามปฏิทินหลังแก้) + `ไม่ย้าย (ซ่อนไว้)`
- **ค่าเริ่มต้นเลือกให้:** ถ้าการบันทึกครั้งนี้ติ๊กเพิ่มวัน Cup ในเดือนเดียวกันพอดี 1 วัน → เลือกวันนั้น; ไม่งั้น `ไม่ย้าย (ซ่อนไว้)` — กรณีย้ายปกติผู้จัดกดบันทึกอย่างเดียว
- ส่ง `sponsorMoves: [{ from, to | null }]` มากับ `cupCalendar`; หลังบันทึกเอกสารจองสำเร็จ (ใน request เดียวกัน) server:
  - `to` = วัน → `UPDATE cup_sponsors SET cup_date=to, updated_at, revision+1 WHERE club AND cup_date=from AND hidden=0`
    ตรวจ `to` ต้องเป็น Cup ตามปฏิทินใหม่และยังไม่เริ่ม ไม่งั้น 400
  - `to` = null หรือไม่ได้ส่งมา → `hidden=1` ทุกแถวของวันนั้น
  - วันที่กลับมาเป็น Cup → แถวที่ `hidden=1` ของวันนั้น `hidden=0`
- ผู้เล่นคนเดียวกันมีแถวทั้งวันเดิมและวันปลายทาง → เก็บแถวที่วันปลายทาง แถววันเดิม `hidden=1` (unique index ไม่ชน)
- ย้ายแล้วเกิน 10 คนได้ ไม่ตัดใคร (เพดาน 10 กันแค่การลงใหม่)
- ช่วงแสดงนับใหม่จากวันใหม่ (วันใหม่ + 7) · ไม่ส่งประกาศ/แท็กซ้ำในกลุ่ม · การ์ดและหน้าจองเปลี่ยนวันเอง

## ช่วงแสดงแถบท้ายการ์ด
- แถวของ Cup วันที่ D แสดงได้ **ตั้งแต่ตอนบันทึก ถึงสิ้นวัน D+7 (23:59 เวลาไทย)**
- **ไม่ซ้อนรอบ:** ในแต่ละก๊วน ณ เวลาหนึ่งแสดงได้ Cup รอบเดียว = วัน Cup ที่เก่าที่สุดซึ่งยังมีแถว `hidden=0` และ `today ≤ D+7`; แถวของ Cup รอบหลังต้องรอจนรอบนั้นพ้น D+7
  ```
  activeSponsors(rows, today):  // rows ของก๊วนเดียว hidden=0
    dates = unique cup_date ที่ addDays(cup_date, 7) >= today, เรียงน้อยไปมาก
    return dates[0] ? rows.filter(r => r.cup_date === dates[0]) : []
  ```
  ตัวอย่าง: Cup 12 ธ.ค. แสดงถึง 19 ธ.ค.; คนลง Cup 9 ม.ค. ตั้งแต่ 15 ธ.ค. → ขึ้น 20 ธ.ค. 00:00 ถึงสิ้น 16 ม.ค.
  ผลข้างเคียงที่ยอมรับ: ถ้ามีคนลง Cup รอบก่อนทีหลัง (รอบหลังขึ้นอยู่แล้ว) รอบก่อนจะแทรกขึ้นแทนจนพ้น D+7
- ไม่มีแถวที่เข้าเงื่อนไข = การ์ดเหมือนเดิมทุกอย่าง ไม่มีแถบ ไม่เว้นที่
- `today` = วันที่ไทย (`bangkokDate`)
- กฎ "รอ" ใช้กับแถบท้ายการ์ดอย่างเดียว: การ์ดขอบคุณในกลุ่มส่งทันที และรายชื่อบนการ์ดวัน Cup ในหน้าจองขึ้นทันที

## หน้าเว็บ (public/booking.js + booking.css)
- `/api/booking` GET เพิ่ม `sponsors` ต่อ session ที่เป็น Cup: `[{ id, name, prize, award, awardNote, message, mine, canEdit, revision }]` (query เดียว `WHERE club=? AND cup_date IN (…) AND hidden=0` ยิงพร้อม query อื่นที่ยิงคู่ขนานอยู่แล้ว)
- การ์ดวัน Cup: ถ้ามีสปอนเซอร์ → กล่อง "🎁 สปอนเซอร์ n คน" ชื่อ · ของรางวัล · มอบให้ (ทุกคน ไม่ตัด สูงสุด 10)
  ปุ่ม `🎁 ร่วมเป็นสปอนเซอร์` (ยังไม่ได้ลง) / `แก้สปอนเซอร์ของฉัน` (ลงแล้ว) — ซ่อนเมื่อรอบเริ่ม/ปิด/งดวันหยุด หรือครบ 10 (ขึ้นข้อความ "ครบ 10 คนแล้ว")
- ฟอร์ม (bottom sheet): ของรางวัล, มอบให้ (ชิป 🥇 แชมป์ / 🥈 รองแชมป์ / 🥉 ที่ 3 / 💩 ท้ายตาราง / ทุกคน / อื่นๆ → ช่องพิมพ์), ข้อความ (ไม่บังคับ), ติ๊ก "แจ้งเข้ากลุ่ม LINE ของก๊วน" (ค่าเริ่มต้นติ๊ก), ปุ่มยืนยัน; โหมดแก้มีปุ่ม "ยกเลิกการเป็นสปอนเซอร์" (ยืนยันในหน้า ไม่ใช้ `confirm()`)
- ผู้จัด: ฟอร์มเดียวกันมีช่อง "ชื่อผู้สนับสนุน" และเห็นปุ่มลบในทุกแถว
- escape ทุกข้อความด้วย `html()`

## API
(ตอนทำจริงเปลี่ยนจาก route `/api/sponsors` แยก เป็น action ใน `/api/booking` แบบเดียวกับ `job` — ใช้เอกสารจอง ตัวตนสมาชิก และ notice เดิม; ตรรกะอยู่ใน `sponsors.js` · ชื่อ action จริง: `sponsorSave` (สร้าง/แก้) และ `sponsorDelete`)
- `POST {action:'create', date, prize, award, awardNote?, message?, displayName? (ผู้จัด), notify}` → `{ sponsor, notice? }`
- `POST {action:'update', id, revision, …fields}` / `{action:'delete', id, revision}`
- `notify=true` และอยู่ใน LIFF → สร้าง notice ชนิด `sponsor` (`createNotice`, payload `{ id }`) คืน `code` ให้หน้าเว็บส่งข้อความเข้ากลุ่มด้วยกลไก `public/line-notice.js` เดิม
- error เป็นภาษาไทย: ไม่ใช่วัน Cup / รอบเริ่มแล้ว / ครบ 10 คน / ลงวันนี้แล้ว / มีคนแก้ก่อน (409)

## LINE
**ประกาศขอบคุณ**
- ข้อความที่ส่งในนามผู้เล่น: `🎁 ขอเป็นสปอนเซอร์ SENA CUP ส. 12 ธ.ค. #xxxxx` (`noticeClub` + `noticeDay`)
- webhook claim notice `sponsor` → ตอบการ์ด `sponsorThanksBubble` ด้วย reply: หัวทอง (`goldHeader`) "🎁 ขอบคุณสปอนเซอร์" + "SENA CUP · ส. 12 ธ.ค.", ชื่อตัวใหญ่, กล่องของรางวัล + ป้ายมอบให้, ข้อความ (ถ้ามี), รายชื่อสปอนเซอร์ทั้งหมดของวันนั้น, ปุ่ม `🎁 ร่วมเป็นสปอนเซอร์` สีก๊วน (ลิงก์ LIFF หน้าจองของก๊วน) — การ์ดนี้มีแถบท้ายตามกฎปกติ
- **แท็กผู้ตีให้รับทราบ (เฉพาะครั้งนี้ครั้งเดียว):** ต่อจากการ์ด ส่งข้อความแท็กตัวจริงของวัน Cup นั้น ณ ตอนที่บอทตอบ (ไม่รวมสำรอง ไม่แท็กตัวสปอนเซอร์เอง)
  เช่น `@Nott @Beau @Ice รับทราบด้วยน้า ขอบคุณสปอนเซอร์กันด้วย`
  - Flex ใส่แท็กไม่ได้ จึงเป็นข้อความแยกตามหลังการ์ด แบบเดียวกับบิลค้าง; ใช้ `planMentionMessages` / `groupMentionTarget` เดิม (≤ 3 แท็กต่อข้อความ, ตรวจสมาชิกกลุ่มก่อน)
  - การ์ด 1 + แท็กได้ 4 ข้อความ (≤ 12 คน) เกินนั้น → Quick Reply "แท็กต่ออีก N คน" (ฟรี ไม่ใช้ Push) แบบ `billTag`
  - คนที่แท็กไม่ได้ (ไม่ผูก LINE, ไม่อยู่ในกลุ่ม, แขก) → ชื่อเป็นข้อความธรรมดาในข้อความแท็ก ไม่มีใครหลุด
  - แท็กไม่สำเร็จ/LINE ปฏิเสธข้อความแท็ก → การ์ดยังต้องส่งได้ (log)
  - ผู้ตีที่จองหลังจากนี้ไม่ถูกแท็กย้อนหลัง (เห็นจากแถบท้ายการ์ดรายชื่อ/หน้าจองแทน)
- แถวถูกลบก่อนบอทตอบ → ไม่ตอบ (ปล่อยเงียบ, log)
- เปิดนอก LINE (ส่งเข้ากลุ่มไม่ได้): บันทึกได้ตามปกติ หน้าเว็บบอกให้พิมพ์ `badbot sponsor` ในกลุ่มเพื่อโชว์การ์ด

**คำสั่ง** `badbot sponsor` / `sponsor sena` / `sponsor 88` → การ์ดรายชื่อสปอนเซอร์ของ Cup ที่กำลังแสดงอยู่ (ตามกฎช่วงแสดง) ถ้าไม่มีแต่มี Cup ถัดไปในหน้าจอง → การ์ดชวน "ยังไม่มีสปอนเซอร์ Sena Cup ส. 12 ธ.ค." + ปุ่มร่วม; `sponsor` (ทุกสนาม) = carousel ก๊วนละใบ เพิ่มใน `help` · **ไม่แท็กใคร**

**แถบท้ายการ์ด** `sponsorStrip(club, rows)` ใน `line-sponsor-card.js` (ใหม่, pure)
- ต่อท้าย `footer` ของ bubble (ถ้า bubble ไม่มี footer ให้สร้าง); พื้นทองอ่อน (Sena) / ฟ้าอ่อน (88), หัว `🎁 SENA CUP ส. 12 ธ.ค. · สนับสนุนโดย` แล้วบรรทัดละคน `ชื่อ · ของรางวัล ป้ายมอบให้` สูงสุด 3 บรรทัด + `+ อีก n คน`
- ใส่ใน: รายชื่อผู้ตี (`rosterBubble`, `emptyBubble`, round), `gamesBubble` (matchup / cupMatchup), `leaderboardBubble`, การ์ดขอบคุณ/คำสั่ง sponsor
- **การ์ดผล Cup (`cupResultBubble`)**: ใช้สปอนเซอร์ของ **วันที่ Cup นั้น** เสมอ (ไม่ดูช่วงแสดง) หัวแถบเป็น `🎁 ขอบคุณสปอนเซอร์ SENA CUP ส. 12 ธ.ค.`
- carousel ทุกสนาม: แต่ละ bubble ใช้แถวของก๊วนตัวเอง
- **ไม่ใส่:** การ์ดน้องขุนเงินทั้งหมด (`owedBubble`, `paidBubble`, ตามบิลตอนเช้า), เมนู Badbot (ไม่ผูกก๊วน)
- อ่านสปอนเซอร์ไม่สำเร็จ → ส่งการ์ดเดิมไม่มีแถบ (ห้ามทำให้คำตอบพัง)
