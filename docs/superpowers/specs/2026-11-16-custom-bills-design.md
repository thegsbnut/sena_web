# บิลอื่นๆ (บิลกินข้าว ฯลฯ) — design

สถานะ: เจ้าของอนุมัติแนวทางแล้ว 2026-11-16 · แผนทำ: `docs/superpowers/plans/2026-11-16-custom-bills.md`
แรงบันดาลใจ: แอปหารบิลแบบ "ขุนทอง"

## เป้าหมาย
สร้างบิลที่ไม่ผูกกับรอบตีแบด เช่น ค่าข้าวหลังตี เก็บเงินผ่านระบบบิลเดิมทั้งหมด (QR พร้อมเพย์ต่อคน, แนบสลิป = จ่ายแล้ว, เงินสด, แท็บบิล + ! แดง, การ์ด/แท็กคนค้างของ Badbot)

## การตัดสินใจของเจ้าของ (ห้ามเปลี่ยนโดยไม่ถาม)
1. **ใครสร้างได้:** ผู้จัด (ล็อกอินแอดมิน) **หรือสมาชิกที่ผูก LINE แล้ว (approved)** — เฉพาะบิลประเภทนี้ บิลตีแบดยังเป็นของผู้จัดเท่านั้น
2. **คนในบิล:** เลือกจากสมาชิกที่ผูก LINE ของก๊วนนั้น (การผูกบัญชี mirror ไปทั้งสองก๊วนอยู่แล้วผ่าน `mapBoth` จึงเห็นคนของทั้งสองก๊วน)
3. **คนนอก = guest ที่ต้องผูกกับสมาชิกหนึ่งคน** ยอดของ guest รวมเข้ากับยอดของสมาชิกคนนั้น (โครง `shares` เดิม: แถวจ่าย 1 แถว หลายคน) guest ไม่มีแถวจ่ายของตัวเอง ไม่ถูกแท็ก
4. **สามวิธีหาร:** หารเท่า · ใส่ยอดเองรายคน · แยกรายการ (แต่ละรายการเลือกคนร่วมจ่ายได้ หลายรายการ)
5. **ปัดขึ้นเป็นบาทเต็มต่อแถวจ่าย** (เหมือนบิลตีแบด)
6. **ไม่นับอันดับ:** ระบบไม่มีอันดับการจ่ายเงิน — 🥇/💩 มาจาก Cup ไม่เกี่ยวกับบิล จึงไม่ต้องทำอะไร ห้ามเพิ่มสิ่งที่เอาบิลประเภทนี้ไปจัดอันดับ

## พฤติกรรม
- **คนรับเงิน (`receiver`)** = สมาชิกหนึ่งคนในบิลที่ออกเงินไปก่อน (ค่าเริ่มต้น = คนสร้าง ถ้าคนสร้างเป็นสมาชิก) · เลขพร้อมเพย์ของบิลเป็นของคนนี้ · แถวของคนรับเงิน (รวม guest ของเขา) ถูกบันทึกเป็น `status:'paid', method:'owner'` ทันที
- ต้องมีอย่างน้อย 1 แถวจ่ายที่ไม่ใช่คนรับเงิน
- **คนจัดการบิล:** ผู้จัด หรือคนสร้างบิล (`createdBy.userId`) ทำได้: เห็นทุกแถว, ดูสลิป, รับเงินสด/ยกเลิกรับเงินสด, ให้ส่งสลิปใหม่, แก้บิล (ก่อนมีคนจ่าย นอกจาก owner), แก้เลขพร้อมเพย์, ยกเลิก/เปิดบิลอีกครั้ง
- **ผล AI ตรวจสลิปเห็นเฉพาะผู้จัด** (กฎเดิม: ห้ามผู้เล่นเห็น) — คนสร้างที่เป็นผู้เล่นไม่เห็น `aiCheck` และกดตรวจซ้ำไม่ได้; ปุ่ม "ตรวจแท็กบิล LINE" และ "บิลทั้งหมด" เป็นของผู้จัดเท่านั้น
- **ชื่อบิล** (`title`) แสดงแทนป้าย "บิลเพิ่มเติม" ทุกที่: หัวหน้าบิล, รายการบิล, ข้อความแจ้งกลุ่ม (`billLabel`), ข้อความ/การ์ดบิลค้าง (`extra`)
- ข้อความแจ้งกลุ่มตอนเปิด/จ่าย/แก้/ยกเลิก ใช้กลไกเดิม (`openedNotice`, `paymentNotice`, `codedNotice`)
- Badbot "bill" แสดงบิลประเภทนี้ปนกับบิลตีแบดของก๊วนนั้นได้ตามปกติ (เป็นบิลค้างของก๊วน)

## ข้อจำกัด (กันสแปม/ข้อมูลเสีย)
| อย่าง | ค่า |
|---|---|
| ชื่อบิล | 1–40 ตัวอักษร |
| จำนวนคน (รวม guest) | 2–40 |
| รายการ (โหมดแยกรายการ) | 1–30 รายการ, ชื่อ ≤ 40 ตัวอักษร, ราคา ≥ 1 สตางค์ |
| ยอดรวม | 1 บาท – 100,000 บาท (≤ 10,000,000 สตางค์) |
| วันที่ | วันนี้ย้อนหลังไม่เกิน 30 วัน ถึงพรุ่งนี้ (เวลาไทย) |
| บิลค้างที่สมาชิกคนหนึ่งสร้างได้ | ≤ 5 ใบที่ยังไม่ปิดและไม่ถูกยกเลิก (ผู้จัดไม่จำกัด) |

## การคำนวณ (หน่วยสตางค์ทั้งหมด)
- ทุกโหมดคิดยอด "ต่อคน" แบบเต็มสตางค์ก่อน แล้วรวมเข้าแถวจ่าย (สมาชิก + guest ของเขา) แล้ว `amount = ceil(sum/100)*100`
- **หารเท่า:** `total` แบ่งให้ทุกคนตามลำดับ `floor(total/N)` + เศษ 1 สตางค์ให้ `total % N` คนแรก
- **ใส่เอง:** ยอดต่อคนตามที่กรอก (≥ 0) `total` = ผลรวม; ต้องมีอย่างน้อยหนึ่งคน > 0
- **แยกรายการ:** แต่ละรายการแบ่งราคาให้คนในรายการแบบเดียวกับหารเท่า (ตามลำดับคนในบิล) แล้วรวมต่อคน; `total` = ผลรวมราคา; คนที่ไม่อยู่ในรายการไหนเลย = ข้อผิดพลาด (บอกชื่อ)
- แถวจ่ายที่ยอด 0 (เช่นใส่เอง 0) ไม่สร้างแถว แต่ถ้าเป็นคนรับเงินยังคงมีแถว owner ได้แม้ยอด 0
- ฟังก์ชันคำนวณใช้ตัวเดียวกันทั้งเบราว์เซอร์และ Worker (`public/custom-split.js` แบบเดียวกับ `public/engine.js`)

## สิ่งที่ไม่ทำ (รอบนี้)
VAT/service charge/ส่วนลด · หลายคนรับเงิน · แก้บิลหลังมีคนจ่าย (นอกจากพร้อมเพย์) · แจ้งเตือนส่วนตัว · ให้ guest มี LINE ของตัวเอง

## หมายเหตุการทำงาน (หลังทำเสร็จ 2026-11-17)
- บิลเก็บใน `bills` เดิม: `payload.kind='custom'`, `session_date='<วันที่>/<uuid>'`; แถวคนออกเงิน `status:'paid', method:'owner'` (ไม่นับเป็น "มีคนจ่ายแล้ว" ใน `started()`; แก้สถานะไม่ได้)
- สิทธิ์: `manager = admin || (kind==='custom' && createdBy.userId === member.userId)`; มุมมองบิลมี `viewer: 'admin'|'creator'`; `slip-check`/ผล AI เฉพาะ admin; ปุ่ม "ตรวจแท็กบิล LINE" และ "บิลทั้งหมด" เฉพาะ admin
- แก้บิลได้ก่อนมีคนจ่ายจริง (ฟอร์มเดียวกัน โหมดแก้ วันที่แก้ไม่ได้) payer id/token คงเดิม; หลังมีคนจ่ายแก้ได้แค่พร้อมเพย์
- หน้า `?custom=new` เปิดฟอร์ม; ปุ่ม "+ สร้างบิลอื่นๆ" อยู่หน้า "ของฉัน" (ผู้จัดหรือสมาชิกที่ผูกแล้ว); สมาชิกเห็น "บิลที่ฉันสร้าง" (`created` จาก `/api/member/bills`)
- ยังไม่ได้ลองใน LINE จริง (ล็อกอิน LINE จริงทดสอบในเครื่องไม่ได้ — จำลอง response ด้วย Playwright)
