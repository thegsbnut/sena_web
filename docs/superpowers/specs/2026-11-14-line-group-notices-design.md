# แจ้งเข้ากลุ่ม LINE ตอนจอง / ถอน / จ่าย — design

## ทำไม
ผู้เล่นทำทุกอย่างผ่าน LIFF แต่คนในกลุ่มไม่รู้ว่าใครจอง ใครถอน ใครจ่ายแล้ว อยากให้กลุ่มเห็นทันที และตัวสำรองที่ได้ขึ้นเป็นตัวจริงต้องได้รับแจ้งเตือน (แท็กจริง)

## ข้อจำกัดที่กำหนดทาง
- LINE OA แพ็กเกจฟรี (300 ข้อความ/เดือน) สองกลุ่มรวม ~60 คน; Push เข้ากลุ่มนับตามจำนวนสมาชิก → ใช้ Push ไม่ได้ (โปรเจกต์ไม่ใช้ Push มาตลอด)
- เจ้าของไม่ยอมให้ LIFF ช้าลง (เคย revert รูปโปรไฟล์เพราะโหลด LINE SDK)

## Approaches ที่พิจารณา
1. **บอท Push เอง** — แท็กจริงได้ ส่งได้ทุกกรณี แต่ ~5 ครั้ง/เดือนก็เต็มโควตา → ตัด
2. **shareTargetPicker** — ฟรี แต่ผู้เล่นต้องเลือกห้องทุกครั้ง → ตัด
3. **(เลือก — เจ้าของเสนอ) LIFF `sendMessages` ในนามผู้เล่น + บอท Reply ฟรี** — ข้อความจาก LIFF เป็นข้อความผู้ใช้ปกติ บอทได้ webhook พร้อม replyToken; ถ้าข้อความมีรหัส `#xxxxx` บอทเอารหัสไปเช็ก D1 แล้วตอบ (Reply ฟรี แท็กจริงด้วย textV2 ได้)

## ข้อความ
LIFF ส่ง text ธรรมดา ใส่ชื่อผู้เล่นในก๊วน (ชื่อ LINE อาจไม่ตรง) · ก๊วนเขียน `SENA` / `88` · วันเป็นแบบ `ส. 16 พ.ย.`

| เหตุการณ์ | LIFF ส่ง (ในนามคนกด) | บอทตอบ |
|---|---|---|
| จอง ได้ตัวจริง | `🏸 ต้น จอง SENA ส. 16 พ.ย. · ตัวจริง 12/16` | — |
| จอง ติดสำรอง | `🏸 ต้น จอง SENA ส. 16 พ.ย. · สำรองคิว 2` | — |
| ถอน ไม่มีสำรองขึ้นแทน | `➖ Nut ถอน SENA ส. 20 พ.ย.` | — |
| ถอน มีสำรองขึ้นแทน | `➖ Nut ถอน SENA ส. 20 พ.ย. #w7f3a` | 1) textV2 `{tom} ได้สิทธิ์เล่น SENA ส. 20 พ.ย. แล้ว 🎉` (แท็กจริง) 2) Flex/ข้อความรายชื่อล่าสุด 16/16 + สำรอง (ใช้ของเดิม `rosterSection`) |
| จ่ายด้วยสลิป ยังไม่ครบ | `💸 ต้น จ่ายบิล SENA ส. 16 พ.ย. 120 บ. สำเร็จ · จ่ายแล้ว 3/12` | — |
| ผู้จัดยืนยันเงินสด ยังไม่ครบ | `💵 ต้น จ่ายบิล SENA ส. 16 พ.ย. 120 บ. สำเร็จ (เงินสด) · จ่ายแล้ว 4/12` (ส่งในนามผู้จัด) | — |
| การจ่ายที่ทำให้ครบ (สลิปหรือเงินสด) | บรรทัดเดียวกับด้านบน + ` #p8k2d` | `✅ บิล SENA ส. 16 พ.ย. จ่ายครบ 12/12 · รวม 1,440 บ. · เงินสด 3 คน: ต้น, บอล, เก่ง` (ไม่มีเงินสดก็ไม่ต้องมีท่อนนี้) |

- "จ่ายแล้ว x/n" นับเฉพาะสถานะ `paid` (สลิปที่แนบ = paid ทันที; เงินสดนับเมื่อผู้จัดยืนยัน)
- **การเลือก (ผมตัดสินเอง):** ผู้เล่นกด "จะจ่ายเงินสด" (ยังรอผู้จัด) → ไม่ส่งข้อความ เพราะยังไม่ได้จ่ายจริง; ข้อความ "สำเร็จ (เงินสด)" ส่งตอนผู้จัดกดยืนยัน
- ผู้จัดยืนยันเงินสดจะส่งได้ก็ต่อเมื่อผู้จัดเปิดหน้าบิลผ่าน LIFF จากกลุ่ม; ถ้ายืนยันจากเบราว์เซอร์ (หน้า admin) จะไม่มีข้อความ

## ความลื่น (ห้ามช้า)
- ตอนกดจอง/ถอน/จ่าย/ยืนยันเงินสด: ยิง API ตามเดิม และ**เริ่มโหลด LINE SDK คู่ขนาน** (ไม่ await)
- API สำเร็จ → แสดงผลสำเร็จทันที → ส่งข้อความเบื้องหลังเมื่อ SDK พร้อม; ส่งไม่ได้ก็เงียบ (log console) ไม่แสดง error ให้ผู้เล่น
- ไม่โหลด SDK ตอนเปิดหน้า และไม่โหลดเลยถ้าไม่ได้อยู่ใน LINE in-app browser
- ปิด LIFF ทันทีก่อนส่งเสร็จ → ข้อความหาย (ยอมรับ)

## ฝั่ง Worker
- ผลลัพธ์ของ API จอง/ถอน/จ่าย/ยืนยันเงินสด คืน `notice: { text, code? }` ที่สร้างฝั่งเซิร์ฟเวอร์ (ข้อความตรงกับ D1 ไม่ต้องคำนวณในมือถือ) — client แค่ส่ง `notice.text`
- ตาราง `line_notices (code TEXT PRIMARY KEY, club TEXT, kind TEXT, payload TEXT, created_at INTEGER, used_at INTEGER)` สร้างแบบ lazy; รหัส 5 ตัว base36 สุ่ม; สร้างเฉพาะถอนที่มีคนขึ้นแทน และการจ่ายที่ทำให้บิลครบ
- webhook: ข้อความในกลุ่มที่ลงท้ายด้วย `#[a-z0-9]{5}` → หา code ที่ `used_at IS NULL` และอายุ < 24 ชม. และกลุ่มนี้ผูกกับ `club` ของ code → mark used (UPDATE … WHERE used_at IS NULL, ชนะคนเดียว) → reply; ไม่ตรงเงื่อนไข → เงียบ
- payload ถอน: club, วันที่, playerId ที่ได้ขึ้น → แท็กด้วย `groupMentionTarget` (ไม่ได้ผูก LINE / ไม่อยู่ในกลุ่ม → ชื่อธรรมดา เหมือนบิล); รายชื่ออ่านล่าสุดตอนตอบ
- payload จ่ายครบ: billId → อ่านบิลล่าสุดตอนตอบ ทำสรุป
- ลบ code เก่ากว่า 7 วันใน cron เดิม

## LINE Developers (เจ้าของต้องทำ — เขียนขั้นตอนใน `LINE-LIFF.md`)
- เพิ่ม scope `chat_message.write` ใน LIFF app; ผู้เล่นต้องอนุญาตครั้งเดียว (client ใช้ `liff.permission.query` ถ้ายังไม่ได้ ข้ามการส่ง; มีลิงก์เล็กๆ ให้กดอนุญาตได้)
- Endpoint ตอนนี้ `/liff.html` แต่หน้าจริงคือ `/court` (+ iframe `/billing.html`) ซึ่งไม่อยู่ใต้ endpoint → **builder ต้องเช็กก่อน** ว่า `liff.init` + `sendMessages` ทำงานบน `/court` ได้ไหม; ถ้าไม่ได้ เปลี่ยน endpoint เป็น root `/` และให้ worker redirect `/?club=…&page=…` / `liff.state` ไป `/liff.html` เพื่อให้ลิงก์เก่าในกลุ่มใช้ได้ ส่วน `liffUrl()` ชี้ `/liff.html`
- `sendMessages` ใช้ได้เมื่อ `liff.getContext().type` เป็น `group`/`room` เท่านั้น (เปิดจากลิงก์ในกลุ่ม) — อื่นๆ ข้าม

## Non-goals / anti-goals
- ห้ามใช้ Push · ห้ามทำให้การเปิดหน้า/การกดจองช้าลง · ห้ามให้การส่งข้อความล้มแล้วกระทบการจอง/จ่าย
- บอทไม่ตอบข้อความจอง/จ่ายปกติ (กันกลุ่มรก)

## เทส
- เทส worker: notice text แต่ละกรณี, สร้าง/ใช้ code ครั้งเดียว, หมดอายุ, กลุ่มผิดก๊วน, reply แท็ก + รายชื่อ, สรุปจ่ายครบพร้อมเงินสด (D1/LINE แบบจำลองตามเทสเดิม)
- ล็อกอิน LINE จริงทดสอบในเครื่องไม่ได้ → หลัง merge เจ้าของลองในกลุ่มจริง
